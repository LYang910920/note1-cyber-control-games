# Reproducibility

## Commands

```bash
python -m pip install -e "../network-control-differential-games[torch]"
python -m pip install -e ".[dev]"
python -m cybergames smoke
python -m cybergames medium --device auto --output-dir artifacts/medium
python -m cybergames figures
python -m cybergames docs
```

`auto` tries MPS, then CUDA, then CPU through the Foundation device resolver. The
choice is recorded in the manifest; importing the package does not select a
device, alter thread counts, or seed global RNGs.

## Smoke and Medium Profiles

`smoke` is an execution/invariant check. It runs short FBS, DDQN, CTDE, MAPPO, and
attacker-defender paths. It is not evidence about learning quality.

`medium` uses five training seeds. It records:

- DDQN evaluation and fixed/rule baselines;
- cooperative MAPPO with summary and graph-context actors;
- held-out node-SIPS parameter strengths and seeds;
- uniform, degree, parameter-risk, oracle, and budget-random policies;
- attacker-defender response rows for static and state-conditioned policies;
- architecture, parameter-count, runtime, and device diagnostics.

The default is bounded for a workstation. Increase episodes, graph sizes, or
opponent retraining only in a separate experiment profile, and record the change.

## Interpretation Checks

Before reporting a learned-policy result:

1. verify the no-action environment against the Foundation ODE;
2. verify flow-only state continuity and reset-only jumps;
3. check SIPS nonnegativity, bounds, and mass conservation;
4. evaluate deterministic policies on held-out seeds;
5. match action budgets across learned and rule-based policies;
6. report both reward and physical metrics such as infected exposure;
7. inspect unilateral deviations for game claims.

A rising training reward is not proof of a Nash equilibrium. A response matrix is
only evidence over the policies and seeds included in that matrix.

## Outputs

All generated JSON, CSV, and temporary figures belong under `artifacts/`, which
is ignored. Curated README figures are regenerated by
`python -m cybergames figures`; only those maintained assets are tracked.
